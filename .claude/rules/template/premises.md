## 前提（ユーザー確定事項）の記録と読み込み

**ユーザーが会話で述べた前提は、書かれた場所に無ければ次の task・サブエージェントで必ず失われる**
（圧縮・新しい task・サブエージェント起動のたびに落ち、同じ違反を繰り返した失敗がある）。
**memory は置き場所にならない**（サブエージェント・共同研究者から見えない）。

### 置き場所（2層）

| 範囲 | 置き場所 |
|---|---|
| **プロジェクト大前提**（epic をまたぐ。データの意味・入力・手法の適用範囲・非循環の条件） | `.spec/invariants.md` の固有節 `## ★ プロジェクト大前提（ユーザー確定事項）`（`P-01` … で番号付け） |
| **epic 前提**（その epic だけの範囲・方針） | epic 本文の `## 前提（ユーザー確定事項）` 節（`/issue-create` の epic 雛形に含まれる） |

- 同じ前提を両方に書かない。epic 前提から大前提は番号（`P-xx`）で参照する。task 本文には原文を写さない。
- 見出しは上の文字列と**完全一致**させる（取得スクリプトが完全一致で切り出す）。

### 読む（必須）

**取得口は `scripts/read-premises.sh <issue番号>` だけ**（親を辿って epic を見つけ、大前提＋epic 前提を原文で出す。自前で抽出しない）。

- メインのセッション: 大前提は `.claude/CLAUDE.md` の import で自動読込。epic 前提は作業開始時に上のスクリプトで読む
- `/task-start`・`/review-spec`・`/task-run`（auto-reviewer・実装・仕様整合性）・`/epic-cycle`（次 task 下書き・達成判定）は
  `$PREMISES` を原文でサブエージェントに渡す。前提違反は Critical／「禁止」で停止
- **設計を示す前に、どの前提に依存し、どれにも反していないかを確認する。前提に反する設計は提示しない。**

### 書く（必須）

- ユーザーが前提・定義・禁止事項・データの意味を述べたら、**その場で**上記いずれかに追記し、追記内容をユーザーに示す。
- **ユーザーの原文（要約するなら原文も併記）と日付を残す。** 言い換えて強めたり弱めたりしない。推測は書かない（不明なら聞く。データ・正解ラベルの意味は、定義が結論を左右するなら分析の前に聞く）。
- **変更・削除はユーザーが明示したときだけ。** 結果や自分の推論に合わせて前提を書き換えない。
  変更したら旧記述を「（YYYY-MM-DD 変更: 旧＝…）」として残す。
- epic の goal / 完了条件が前提と矛盾していたら、書き換えずにユーザーに報告する。

節が無い既存プロジェクトの移行手順は `premises-migration.md`（`read-premises.sh` の WARN が案内する）。
