# Invariants（変更禁止の設計判断）

> このファイルは `auto-reviewer` エージェントが**判断前に必ず読む**必須コンテキストです。
> プロジェクト開始時、および重要な設計判断を下すたびに追記してください。

ここには「**一度決めたので、覆すなら明示的な合意が必要な設計判断**」を書きます。
`core-rules.md`（絶対ルール）と違い、**正当な理由があれば変更できます**が、勝手に変えてはいけません。

## 書き方

```markdown
### INV-001: <設計判断の名前>

**決定**: <何をどう決めたか>
**理由**: <なぜそう決めたか>
**決定日**: YYYY-MM-DD
**関連Issue**: #N
**変更する場合**: <何を確認・合意すれば変更してよいか>
```

# 既定の設計判断（テンプレート同梱）

テンプレートが前提としている設計判断です。**プロジェクト側で覆すことは可能**ですが、
その場合はワークフロー側の調整が必要になるため、変更理由を Issue に残してください。

### INV-D01: 作業は必ず worktree 内で行う

**決定**: メインディレクトリで直接作業せず、Issue ごとに `worktrees/issueN` を作る
**理由**: 並行タスクでブランチがコンタミネーションするのを防ぐ
**変更する場合**: 並行作業を行わないと確約できる場合のみ

### INV-D02: worktree は相対パスで作成する

**決定**: `git worktree add --relative-paths` を使う（`worktree.useRelativePaths=true`）
**理由**: ホストと devcontainer でマウントパスが異なるため、絶対パスだと
worktree を作成した側の環境でしか git / gh が動かない
**変更する場合**: devcontainer を使わず、単一環境でのみ作業すると確約できる場合のみ

### INV-D03: 重要データは `data/shared/` に置く

**決定**: データセット・実験結果・学習済みモデルは `data/shared/` に配置する
**理由**: worktree 削除時のデータ消失を防ぐ。`/tmp` や `~/.cache` は devcontainer rebuild で消える
**変更する場合**: 別の永続化手段が確立されていること

### INV-D04: experiment の成果物は3点セットで残す

**決定**: 生データ・図・README の3点を `data/shared/experiments/` に揃える
**理由**: 結論だけでは再現・検証ができない
**変更する場合**: 代替の再現手段が確立されていること

### INV-D05: negative result には格付けを付ける

**決定**: `unverified-negative` / `verified-negative` / `implementation-bug` のいずれかを必ず付す。既定は `unverified-negative`
**理由**: 検証済みか未検証かを区別せずに記録すると、未検証の結論が既成事実として伝播する
**変更する場合**: なし（`.claude/rules/template/experiment-discipline.md`と一体）

## auto-reviewer への指示

- ここに記載された判断に反する実装は「**警告付き許可**」ではなく「**禁止**」とし、Issue で合意を取るよう促すこと
- **既定の設計判断が揃っていれば「必読コンテキストあり」と判定してよい。**
  ただし「プロジェクト固有」節が未記入の場合は、判断ログにその旨を記録すること
