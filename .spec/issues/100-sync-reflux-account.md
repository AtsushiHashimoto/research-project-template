## 1. 決定事項

### D1: テンプレート由来ルールは `.claude/rules/template/` に隔離する

```
.claude/rules/
├── template/          ← テンプレート由来。sync がディレクトリごと置き換える
│   ├── issue-hierarchy.md
│   ├── ...（#91 の10ファイル + model-policy.md）
│   └── MANIFEST.sha256    ← 各ファイルのハッシュ一覧（D1-b で使用）
└── *.md               ← プロジェクトローカルのルール。sync は一切触らない
```

**根拠**: 規約（「rules/ に固有記述を書くな」）は破られうるが、ディレクトリ分離なら
sync 対象が機械的に確定する。パススコープ付きローカルルールの正当なユースケースも保存される。

#### D1-a: sync はアトミックに行う（レビュー指摘 F1 対応）

```bash
# ❌ 禁止: rm -rf → cp は cp 失敗時に部分適用状態になる
# ✅ 一時領域に展開してから mv で入れ替える
cp -r "$TMP/template/.claude/rules/template" "$RULES_DIR/.template.new" \
  && rm -rf "$RULES_DIR/template" \
  && mv "$RULES_DIR/.template.new" "$RULES_DIR/template"
```

取得・展開に失敗した場合は**何も変更せず、非0 exit ＋ エラーメッセージで終了**する
（exit 0 の無言終了は sync 済みと誤認させるため禁止。レビュー指摘 F3 対応）。

#### D1-b: sync はローカル改変を検出してから置き換える（レビュー指摘 F2 対応）

**sync が contribute の還流候補を黙って破壊してはならない。**

1. `template/MANIFEST.sha256`（前回 sync 時点のハッシュ）と現ファイルを照合
2. 不一致（ローカル改変あり）のファイルは:
   - `.claude/rules/template.bak-<日付>/` に**退避コピー**してから置き換える
   - 終了サマリに「還流候補 N 件を退避した。/template-contribute を実行してください」と表示
3. MANIFEST が無い場合（初回 / 旧構造）は全ファイルを改変扱いとして退避する

#### D1-c: 修正対象の既存ファイル（レビュー指摘・設計1 対応）

D1 適用時に**同一 PR で**修正しなければならないファイル:

| ファイル | 修正内容 |
|---|---|
| `.claude/rules/*.md`（11ファイル） | `template/` へ移動。**相互参照パス**（`labels.md`→`experiment-discipline.md` 等）を更新 |
| `.claude/CLAUDE.md` | 「ルールの所在」表のパスを `template/` 化。「rules/ に固有記述を書くな」の警告を「**rules/ 直下はローカル用、template/ は書き換え禁止**」に差し替え |
| `.claude/skills/template-sync/SKILL.md` | `rm -rf .claude/rules/` を D1-a/b の手順に差し替え |
| `.claude/skills/template-contribute/SKILL.md` | 検出対象パスを `rules/template/` 化（D4） |
| `.claude/skills/issue-finish/SKILL.md` | D4-b の契機組み込み。あわせて既存不整合（`in-progress` ラベル削除処理が labels.md の「使わない」と矛盾）を解消 |

**実装順序の制約（設計2 対応）**: ディレクトリ移動と template-sync の処理変更は
**必ず同一 PR で行う**。分かれると、その間の sync 実行が rules/ 直下のローカルルールを
`rm -rf` する破壊的動作になる。

### D2: `.spec/` の既定節はマーカー方式で差し替える

`^# 既定の` から `^# プロジェクト固有` の直前までを機械的に差し替える
（実現性レビューで3ファイルとも一意マッチを確認済み）。実装は `scripts/sync-spec-defaults.sh`。

- **冪等**: 同一テンプレートに対し2回実行しても結果が一致する（V8 で検証）
- マーカーが見つからないファイルは**スキップし、終了サマリに明示＋非0 exit**
  （警告のみだと壊れた .spec が永久に更新されない「静かな腐敗」になる。F3 対応）
- **構造変更**: `## auto-reviewer への指示` 節（現在は固有節の後ろ）を**既定節の末尾に移動**する。
  現位置ではテンプレート側の更新が永久に伝播しない（実現性レビューの指摘）

### D3: アカウント単位化（`~/.claude/`）は配布手段として採用しない

| 検討軸 | `~/.claude/` 配布 | リポジトリ内（D1）＋sync |
|---|---|---|
| 共同研究者の環境 | ルールが無くワークフロー崩壊 | clone だけで揃う |
| devcontainer | ホストの `~/.claude` はコンテナに無い | リポジトリごとマウントされる |
| 更新の伝播 | 全マシンで手動更新 | sync 1回 |
| 外部インポート `@~/...` | 承認ダイアログ拒否で恒久無効化の罠 | 不使用 |

AGENTS.md 階層標準（nearest-file-wins）は方針として存在するが、**「最も近いファイルが勝つ」
という優先則こそが「リポジトリ内配置が正」を意味する**。アカウント層は個人の好み
（言語・出力スタイル等）にのみ使う。この使い分けをガイドとして
`.claude/rules/template/doc-principles.md` に1節追記する（V9 で検証）。

**#74 との関係（設計3 対応）**: 設計レビューは「D3 は #74 の goal の書き換えに**該当しない**」
と判定した（完了条件が手段非依存で書かれており、アカウント単位化は「提案（要相談）」の
方針1にすぎず、その論点への回答であるため。KI-D14 非該当）。ただし以下の手当てを行う:

- #74 に決定コメントを残し、タイトルから「アカウント単位化」を外す
- #74 の完了条件のうち「成果物リリース時に開発ファイルが混入しない」は **#102 に切り出し済み**
- 「PushVoice 71行運用の分析」は D3 不採用により根拠として不要になったため**スコープ外と宣言**する

### D4: contribute は「テンプレート由来ファイルの diff 検出」で半自動化する

**使われなかった原因の仮説**: (1) 切り出しコストが高い (2) 判別基準が無い (3) 契機が無い

#### D4-a: 判別の機械化

`/template-contribute` は `rules/template/`・`skills/`・`scripts/`・`agents/` について
テンプレート最新版との diff を取り、変更ファイル一覧を提示して選択させる。
D1-b の退避ディレクトリ（`template.bak-*`）も検出対象に含める。

生成する PR 本文には「元 issue・動機・汎用性の根拠」を含める（V5 で形式を検証）。

#### D4-b: 契機の組み込み

`/issue-finish` の完了報告時、テンプレート由来パスに変更が含まれていたら
「還流候補があります」と1行提示する。

- **auto モードの検知**: `/task-run` 経由の呼び出しでは `/commit-merge --auto` の機構に従う
  （既存実装）。auto 時は質問せず、**issue の完了報告コメントに還流候補一覧を記録**するのみ
- 対話モードでも提示は非ブロッキング（質問ではない）

### D5: 旧構造からの移行手順

検出条件: `.claude/rules/` が無い（543行世代）**or** `rules/template/` が無い（#91 フラット世代）。

#### D5-a: #91 フラット世代の孤児ファイル処理（実現性レビュー対応）

`.claude/rules/` 直下のファイルをテンプレート既知ファイル一覧（MANIFEST）と突合:

| 判定 | 処理 |
|---|---|
| テンプレート旧版と内容一致 | 削除（template/ の新版に置き換わる） |
| 改変あり | **還流候補として退避**（D1-b と同じ機構）し、ユーザー確認へ |
| 一覧外のファイル | ローカルルールとして**保持** |

これを行わないと旧版と新版が二重に読み込まれ、矛盾したルールが同時注入される。

#### D5-b: 543行世代の CLAUDE.md

重複部分を diff 提示し、固有部分の抽出は**ユーザー確認つき**（自動では削らない）。
auto モードではこの移行は行わず、user-action として issue を起票する。

## 3. Fallback ホワイトリスト

| 許可される fallback | 条件 |
|---|---|
| テンプレート取得失敗 → 無変更終了 | **非0 exit ＋ エラーメッセージ必須**（無言 exit 0 は禁止） |
| .spec/ マーカー不在 → スキップ | **非0 exit ＋ サマリに明示必須** |

**禁止**: 固有記述の自動削除、確認なしの CLAUDE.md 書き換え、退避なしの template/ 上書き。
