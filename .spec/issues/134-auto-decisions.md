**(a) スキップ判定の欠陥（条件3・必須）**: PR #128 原案のコードは
`[ -z "$PARENT" ] && スキップ` で「親の有無」しか見ておらず、**親のラベルを確認していない**。
仕様の「対象 issue が epic / task の子である場合のみ実行」と実装が食い違う。
小タスク（親＝issue 層）では親 issue に対してチェッカーが走ってしまい、挙動が未定義になる。
実装時は**親のラベルで分岐を固定**すること:
- 親なし → スキップ（原案どおり）
- 親が epic → `## 完了条件` と照合
- 親が task → `## 目標の状態` の「成功条件」と照合
- 親が issue 層（小タスク）→ 親 issue の `## 完了条件` と照合するか、明示スキップするかを仕様に明記（どちらでもよいが未定義にしない）

**(b) 件数表記**: 原案の「7つのサブエージェント」を取り込まない方針は #119 D4 と整合し正しい。
ただし**現行 main の review-spec SKILL.md L398 に「6つのサブエージェント」が残存している**
（仕様の「#119 D4 で全廃した」という記述は現状と厳密には一致しない）。
チェッカーを追加してこの行を放置すると即座に虚偽（6つと書いて7つある）になるため、
実装時に L398 を件数なしの表現（例:「全サブエージェントの結果を統合し」）へ修正すること。
V4 がこれを捕捉できる書き方になっているのは適切。
番号 3-4b は既存 3-4（Fallback）と 3-5（妥当性検証）の間で整合する。
