# Issue #134 仕様: goal を小さく読む逸脱の検出

- 状態: approved（auto-reviewer 判断済み。条件1〜5を反映。ログ: 134-auto-decisions.md）
- 出自: PR #128 / `omron-sinicx/delta-clip-dev#151`

## 背景（下流で実際に起きた失敗）

epic の完了条件に「B の測定値と合否を記録」「C の測定値と合否を記録」と明記されていたのに、
先行する A が FAIL した時点で「上位の合格条件（A AND B）を満たせないから以降は不要」と判断し、
**B・C を未着手のまま epic ごとクローズした**。

**goal は「Go/No-Go を判定する」ことであり、No-Go を出すこと自体が達成条件だった。**
さらに落とした B・C は A とは別の仮説を検証するもので、A の結果は実施可否を左右しなかった。

既存の `auto-reviewer` は「goal の**書き換え**」（結果に合わせて goal を変える）を
禁止していたが、その**逆方向** — 自分の推論に合わせて goal を小さく読む — に
チェックが無かった。書き換えが「goal を結果に合わせる」なら、これは
「goal を自分の推論に合わせる」で、**どちらも goal が実際より小さくなる**。

分岐元が古く、`git diff main pr128` には**今日の #115（#116〜#122）と #133 の成果を

template-source.sh 削除、.spec/issues/121・122・133 削除 など）。

**goal 整合の追加部分だけを抽出し、現在の main の上に適用する。**

取り込まないもの（今日の修正の巻き戻しにあたる）:

## 設計

### D1: auto-reviewer に「ゴールへの整合」節と停止条件 S7 / S8 を追加

「ゴールの書き換え（最優先で確認）」の直後に、逆方向の逸脱を扱う節を置く。

| パターン | 判断 |
|---|---|
| 子 issue が親の**どの完了条件に対応するか**を示せる | ✅ |
| 完了条件に対応しない作業を epic 配下に追加する提案 | ⚠️ 警告付き許可（対応関係を判断ログに記録）。**goal の文言を変えずに作業を足す場合のみ。goal 自体の範囲を書き換える提案は ❌**（条件1。この括弧書きが無いと範囲拡大が「作業追加」として通る抜け道になる） |
| **完了条件が未充足のまま** epic / task を閉じる提案 | ❌ |
| 「上位が満たせないから下位も不要」で未着手の子を落とす提案 | ❌ |
| 子を「不要」と判断する根拠が goal に明示されていない | ❌（ユーザー判断を仰ぐ） |

停止条件を追加する:

- **S7**: epic / task を閉じる提案で、完了条件のうち未充足の項目がある。
  完了条件が未記入・曖昧で照合そのものができない場合も停止する。
  **チェックボックスの機械的な未チェックではなく実質の充足で判定する**
- **S8**: 未着手の子 issue を落とす提案で、その根拠が親の完了条件に明示されていない。
  **操作的定義（条件2）**: 親の完了条件から該当項目を**原文引用できなければ
  「明示されていない」とみなす**（KI-D13 と同じ型で機械的に判定する）

既存の `S1〜S6` 参照箇所（auto-reviewer / task-run / epic-cycle）を `S1〜S8` に更新する。

### D2: issue-hierarchy.md に規律を追加

「★ ゴールの不変性」の直後に「★ goal を小さく読まない（書き換えの逆方向）」を置く。

### D3: review-spec に「epic goal 整合チェッカー」を追加

対象 issue が epic / task の子である場合のみ実行し、親が無ければスキップして
その旨を出力する。観点は「対応関係 / 範囲の切り縮め / 独立性 / クローズ条件」。

**節名は層で異なる**ことを明記する: epic / issue は `## 完了条件`、
**task は `## 目標の状態` の「成功条件」**。

**★ 件数表記（条件3）**: PR #128 の原文は「7つのサブエージェント」と書いている。
**#119 D4 の件数全廃は `review/SKILL.md` と `skills.md` が対象で、
`review-spec/SKILL.md` は対象外だった**（仕様の当初記述は不正確。auto-reviewer 指摘）。
実際に `review-spec/SKILL.md:398` に「6つのサブエージェント」が残存している。
**チェッカー追加と同時にここも件数なしに直す**（さもないと 6→7 のずれが新たに生まれる）。

**★ スキップ判定（条件3）**: 原案は `[ -z "$PARENT" ]` だけで**親のラベルを見ていない**。
親のラベルで分岐を固定する:

| 親の層 | 参照する節 |
|---|---|
| epic | `## 完了条件` |
| task | `## 目標の状態` の「成功条件」 |
| issue（＝小タスク） | 照合しない。**明示的にスキップ**し、その旨を出力する |
| 親なし | スキップし、その旨を出力する |
