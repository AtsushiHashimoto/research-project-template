### 3. D3: ファイル単位検査の限定と「限定しないもの」の線引き

| 項目 | 内容 |
|------|------|
| 質問 | skill-refs / skill-labels を全件のままにする判断は正しいか。逆に限定すべきものを外していないか |
| 判断 | ⚠️ 警告付き許可 |
| 理由 | **線引きの原則は妥当**: 「ファイル単位で完結する検査（shellcheck / ruff）は変更ファイル限定、グラフ的・全体的性質の検査は全件」。skill-refs / skill-labels は参照整合というリポジトリ全体の性質であり、スキルを1つ消したとき参照側ファイルは変更されないため、変更ファイル限定では検出原理が壊れる（全件維持が正しい）。またこれらは grep ベースで軽く、下流で赤なら実行経路が死んでいる実害（#117/#118）なのでブロックしてよい。MANIFEST 整合・pytest の全件維持も同じ理由で正しい |

| 警告2（shebang 収集） | 限定は「#121 の収集ロジック（`*.sh` + shebang 判定）と変更ファイル集合の**積**」で行うこと。pr129 の `changed_of sh` は拡張子マッチのみで、拡張子なしスクリプトが素通りする。V9 が pin しているが実装時に注意 |
